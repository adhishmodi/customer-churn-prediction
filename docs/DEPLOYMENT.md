# Phase 7C — Render deployment

## Hosting target

Deploy `app.py` from the repository's `main` branch to a Render Python Web
Service in the approved workspace. Start with the Free plan and Singapore
region. The service is public and does not provide authentication.

Use these service settings:

| Setting | Value |
|---|---|
| Runtime | Python |
| Python version | 3.12 (pin the current compatible 3.12 patch; currently 3.12.11) |
| Branch | `main` after the deployment PR is merged |
| Build command | `pip install -r requirements.txt` |
| Start command | `streamlit run app.py --server.address 0.0.0.0 --server.port $PORT --server.headless true` |
| Plan | Free |
| Region | Singapore |
| Auto-deploy | On commit |

Render injects the `PORT` variable. Streamlit must bind to `0.0.0.0` and
that port so Render's public proxy can reach it. The Free service can spin
down after inactivity; expect a cold start when a visitor returns.

## Model artifact handling

The app reads two values through Streamlit Secrets:

- `MODEL_ARTIFACT_B64`: Base64-encoded bytes of the trusted
  `customer_churn_model.joblib` generated by Notebook 12.
- `MODEL_ARTIFACT_SHA256`: SHA-256 hex digest of those exact artifact bytes.

The repository's `.streamlit/config.toml` maps the Render Secret File
`/etc/secrets/secrets.toml` into Streamlit's secrets configuration. The
application rejects missing secrets, malformed Base64, oversized artifacts,
malformed checksums, and checksum mismatches before calling the existing
trusted `load_model_artifact()` validator. The temporary artifact file is
created with restrictive temporary-file permissions and removed after
loading. The loaded bundle is cached in the Streamlit process.

Never commit the model artifact, Base64 payload, checksum, secrets file, raw
customer data, or customer uploads to Git. Do not accept model binaries from
visitors. The checksum is an integrity check; it does not make an untrusted
joblib artifact safe. Only use the artifact generated by your own Notebook 12
run.

## Prepare the private secret file

Run Notebook 12 and obtain its generated
`models/customer_churn_model.joblib`. In the same trusted Colab runtime (or
after uploading that artifact into a trusted runtime), run:

```python
from pathlib import Path
import base64
import hashlib

artifact = Path("models/customer_churn_model.joblib").read_bytes()
print("MODEL_ARTIFACT_B64 = " + base64.b64encode(artifact).decode("ascii"))
print("MODEL_ARTIFACT_SHA256 = " + hashlib.sha256(artifact).hexdigest())
```

In the Render Dashboard, open the service, select **Environment**, then
**Secret Files** → **Add Secret File**. Set the filename to
`secrets.toml` and paste the following TOML structure, replacing both
placeholders locally with the generated values:

```toml
MODEL_ARTIFACT_B64 = "PASTE_THE_BASE64_VALUE"
MODEL_ARTIFACT_SHA256 = "PASTE_THE_SHA256_VALUE"
```

Save the secret file. Render mounts it at
`/etc/secrets/secrets.toml` and triggers a deploy. Do not paste the actual
Base64 value or checksum into ChatGPT, GitHub, a pull request, or a public
notebook. The Base64 value is the private model artifact, not public
configuration. Render currently limits the combined secret files for a
service to 1 MB; confirm the generated file fits before saving it.

## Deploy and verify

After the deployment PR is reviewed and merged:

1. Confirm the Render service is linked to
   `adhishmodi/customer-churn-prediction` on branch `main`.
2. Confirm the Python runtime is pinned to a supported Python 3.12 patch.
3. Confirm the build and start commands match the table above.
4. Add the private `secrets.toml` Secret File as described above.
5. Wait for the Render deploy to reach **Live**.
6. Open the public `onrender.com` URL in a private/incognito browser session.
7. Confirm the model loads and the Phase 7A calibration and stored threshold
   appear in the sidebar.
8. Submit a synthetic single-customer prediction.
9. Upload a valid CSV with exactly the 19 model features; confirm row count,
   row order, and downloadable prediction CSV.
10. Confirm missing/extra columns, malformed CSV, and uploads over 10 MB are
    rejected. Inspect the downloaded CSV for formula-like values.
11. Inspect recent runtime logs for errors and confirm no artifact secret or
    customer data is logged.

Record the public URL and deployed revision only after these checks pass.
A successful service creation or deploy request alone is not proof that the
application is healthy or usable.

## Privacy, access, and operational limits

This app is intentionally public and unauthenticated. Anyone with the URL can
submit requests and consume the shared app resources. The 10 MB upload and
10,000-row batch limits reduce individual request size but are not an
authentication system, rate limiter, or abuse-prevention guarantee. Do not
use real customer personal data or sensitive information in this portfolio
demo.

The app itself does not write customer rows to a database or persistent
application store. Uploaded data is still processed by the hosting provider's
runtime; in-memory app handling is not a promise that the hosting provider
never handles data. Review Render's current terms and data-handling
information before sharing real customer data.

Render Free web services may spin down after 15 minutes of inactivity and
may have cold starts. Free-tier resource limits make this suitable for a
portfolio demonstration, not a production customer-facing service with
uptime, access-control, or capacity requirements. No database, external API,
or paid service is introduced by this phase.

## Model and validation boundaries

Phase 7C only packages and serves the already-built Phase 7A model. It does
not train, tune, recalibrate, choose a threshold, or evaluate predictive
performance. The historical 1,409-row holdout remains permanently excluded
from all future work in this phase.
